v5: TOPの集計表示を削除。営業中表記を簡略化。曜日を選んで営業時間をコピーでき、営業時間の一括クリアを追加。関連URLは食べログ・X・Instagramのトグルと自由入力を併設。

外食候補リスト PWA v2

【機能】
ジャンル複数トグル選択、出発地からGoogleマップ経路検索、所要時間の手動記録、通し営業・2部制・各L.O.、3状態、登録・更新日時、JSON入出力。Firebase設定でPC/iPhone自動同期。

【公開】
HTTPSのGitHub Pagesなどにフォルダ内全ファイルをアップロードしてください。index.htmlをダブルクリックするだけではPWAとして動作しません。

【Firebase自動同期の有効化】
1. Firebaseコンソール https://console.firebase.google.com/ でプロジェクトを作成。
2. Authentication（認証）→Sign-in method（ログイン方法）→Googleを有効化。
3. Authentication→Settings→Authorized domains（承認済みドメイン）にPWAの配信ドメイン（例 username.github.io）を追加。iPhoneでGoogleログインのポップアップが制限された場合、別のブラウザから試してください。
4. Firestore Databaseを作成。必ず firestore.rules の内容を「ルール」にコピーして公開。テスト用の誰でも読めるルールのまま運用しないでください。
5. Firebaseの「プロジェクトの設定」→「マイアプリ」→ウェブアプリで設定値を取得。firebase-config.js の window.FIREBASE_CONFIG に apiKey,authDomain,projectId,appId を含めて記入。Firestore用の設定は秘密鍵ではありません。ルールと認証がアクセスを制限します。
6. ファイルを再アップロードし、PC/iPhoneの両方で同じGoogleアカウントでログイン。

【既存データの移行について】
端末に保存していた旧v1データは読み込まれ、旧「訪問済み」は「訪問済み・判定待ち」へ移されます（リピートの意思は旧データに無いため、編集して振り分けてください）。移行後は必ずJSONバックアップを取得してください。
初回クラウドログインではクラウド側の一覧が表示され、端末内の既存データは自動アップロードされません。ログイン前にJSONバックアップを書き出し、ログイン後に「バックアップを読み込む」からクラウドへ取り込んでください。

【注意】
・Firebase未設定・未ログイン中は端末内保存のみであり、自動同期されません。
・Googleマップからの移動時間自動取得は行いません。出発地は設定画面で記録し、Googleマップの経路結果に基づき分数を手入力してください。
・出発地設定はログイン時に同期されます。自宅住所の代わりに最寄り駅を設定すると個人情報を減らせます。
・オフライン時の未反映編集を確実に保持するにはネットワーク復帰後に同期完了表示を確認してください。
・既存のバックアップJSON v1も読み込み可能です。

【v4 変更点】
・曜日別の営業時間（通し営業／2部制／定休日／未確認）と、各時間帯のラストオーダーを登録できます。
・月曜日の時間を全曜日に複製してから曜日別に調整できます。
・店舗住所から都道府県と市区町村を抽出してエリアを設定します。外部の住所検索APIは使用しません。住所の表記によっては抽出に失敗することがあります。
・「関連URL」は名称付きで何件でも登録できます。旧版の店舗URL・地図URLは自動変換して表示します。
・一覧で当日の定休日を灰色に表示し、現在営業中（登録情報に基づく）などで絞り込めます。祝日、臨時休業、例外営業時間は自動判定されません。
・古い「訪問済み・判定待ち」状態は新しい画面では「未訪問」に置き換わります。必要なら登録後にリピート有無を編集してください。
・既存データの営業時間は旧表記で保持されます。各店を編集し、曜日別スケジュールを新たに入力すると営業状況判定が有効になります。
・Firebase設定、既存店舗のID、登録・更新日時は保持されます。
・公開時はフォルダごとではなく中身だけをGitHubリポジトリのルートへアップロードしてください。
・ファイル更新前に、アプリ画面でJSONバックアップを書き出すことを推奨します。
